# Result artifacts

Store raw benchmark JSON and derived CSV files here when publishing a performance
claim. Use host-specific names such as `ryzen-7535hs-python312.json`. Keep the raw
samples and environment metadata generated by the CLI; do not commit only a copied
Markdown table.

Large or exploratory outputs may remain untracked. A reviewed result should include
the exact command in its pull request or accompanying analysis and should distinguish
logical bytes scanned from hardware-measured DRAM traffic.

The `ryzen-7535hs-*` artifacts form one reviewed case study:

- controlled timing JSON/CSV and SVG;
- isolated RSS measurements;
- random and sorted-within-bag embedding JSON plus a paired same-seed analysis;
- Numba LLVM IR plus an environment and hash sidecar;
- Python object-layout, tracing, RSS, bytecode, and GIL evidence;
- paired CPython 3.14 standard/free-threaded raw timing samples;
- `ryzen-7535hs-analysis.md`, which interprets the evidence and states its limits.

No `perf stat` artifact is included: the recorded host denied PMU access with
`perf_event_paranoid=4`. The profiler and normalization scripts are available, but
their proposed events must not be described as measured evidence until a permitted
capture is checked in.
